# Brief: case furniture of the Pinskdrev catalogue (cloud session)

The "House" app (Unity 6) builds houses from JSON; its furniture library now takes **case furniture as data**: every
module of a manufacturer's catalogue is a design file — the list of the module's real parts at their real positions —
built by a C# engine. The first collection, **«Флора»** (11 modules), is done and checked: study it, then author the
collections of your wave the same way. The user wants the furniture **one to one** with the catalogue: sizes to the
millimetre, the same construction, the same look.

There is no Unity here. You check everything with the Python tools; the lead renders all of it in 3D afterwards and fixes
what the engine cannot do. **Do not edit C#** or anything outside the paths listed under "Output".

## Read first
- `Docs/casegoods-designs.md` — the format (parts, fronts, faces, mouldings, handles, moves, catalogue) and the workflow.
- `Assets/House4696/Resources/Casegoods/catalog.json` — finishes, the Flora profile, collections, models.
- `Assets/House4696/Resources/Casegoods/Designs/flora-*.json` — finished designs (hand-written 0-01 … 0-05; generated by
  `tools/casegoods/gen/flora_wardrobes.py`, `flora_bed_mirror.py`), `_features-a.json`, `_features-b.json` — every engine
  feature in use (fluted / frame / grooves / diamond fronts, rods, tapered splayed legs, glazing bars, tinted glass, a
  mirror sliding door, flaps, a buttoned soft panel, an arched top by an SVG outline, a finish with roles).
- `tools/casegoods/reference/index.json` — every article of the catalogue: code, name, collection, catalogue size
  [L, B, H] (beds: L = length), pages, colours, the site's product url, `slug` (the collection's id) and `pdf` (the
  assembly instruction). Articles with `"check"` were read unsurely from the PDF text: confirm them on the page.
- `tools/casegoods/reference/<slug>/cutlists/<model id>.json` — each module's cut list (parts, three sizes, count), and
  `pages/<model id>.png` (the table page: the front / back views with the part numbers) + `-cover.png` (the overall
  drawing with the sizes). Some rows are missing in the JSON (broken text in the PDF): read them from the page image.
  Four table formats exist: the current one (code + three sizes), «номер, код, наименование, кол.» without sizes (the
  sizes are dimension lines on the drawing — read them), «наименование, материал (ЛДСП 16мм ДУБ КАНЬОН), кол., two
  sizes» (it names each part's decor: use it for the finish roles) and «наименование, AхB, кол.». Instructions without a
  text layer have `pages/<id>-p1.png … -p4.png` instead: read the table from the pictures.
  **About a third of the modules have an instruction.** For the others there is no cut list: build them from the
  catalogue (the module cut-outs on the collection's last spread, the interior photos, the close-ups) and the site's
  product photos, with the collection's instructed modules as the model of its construction (the same board
  thicknesses, fronts, gaps, mouldings, legs, plinth, handles, drawer boxes); the extent must still equal the catalogue
  size. Say in the notes which modules are "by photo".
- Product photos: `index.json` → `photos` (pinskdrev.by, no login; `curl -A "Mozilla/5.0" -o x.jpg <url>`), `site`
  (the product page on pinskdrev.by: more photos, the colour variants). The .ru site is behind a JS check — use .by.
  Instructions not yet in `reference/`: `pdf` (a.pinskdrev.ru, curl works) → `python3 tools/casegoods/prepare_refs.py
  --collections <slug>`.
- `tools/casegoods/reference/catalog_km2.pdf` — the catalogue (148 pages = spreads). The interior photos, the module
  cut-outs, the swatches of the colours and the close-ups of fronts and handles are there: render a page with
  `pdftoppm -r 150 -f N -l N -png` (poppler; `apt-get install poppler-utils` or use PyMuPDF) and crop what you need.
- Python: numpy + Pillow (`pip install numpy pillow`).

## Per module
1. `python3 tools/casegoods/cutlist.py …` is already done for you (the cutlists folder); open the page PNG and the cover.
2. Work out the construction: which panels stand on which (tops / bottoms spanning the sides or the sides running full
   height), the plinth or legs, backs in grooves, partitions, fixed and loose shelves, cleats and spacers, fronts and
   their gaps, drawer boxes, frames of mouldings, the handles and their positions, rails and lights. The drawings are to
   scale (take the scale from the overall size); the catalogue photos show the look (profile of the fronts, handle,
   legs, colours of each part in two-decor finishes).
3. Write `Designs/<model id>.json` (or a generator in `tools/casegoods/gen/<slug>.py`), add the model to catalog.json.
4. `python3 tools/casegoods/preview2d.py Assets/House4696/Resources/Casegoods/Designs/<id>.json --ref <page png>
   --ref-box x0,y0,x1,y1 --out tools/casegoods/pilot/<id>.png` must print `ok` (cut list, extent, no overlaps), and the
   red outline must sit on the instruction's front view. Look at every sheet (Read the PNG) and iterate.

## Finishes and decors
- Plain colours: `door_enamel_whitey#rrggbb`, the colour read from the catalogue's swatch of that colour (the swatch
  pages of each collection) — average a flat crop; say which page.
- Wood, stone, concrete and other textured decors (Дуб Каньон, Дуб Саттер, Сосна Карелия, бетон …) do not exist yet: give
  every such finish role a **provisional** plain colour (the decor's mean colour from its swatch) AND list the decor in
  `tools/casegoods/decors.md` (name as the catalogue writes it, collections using it, catalogue page of the swatch,
  character: oak cathedrals / planks / knots / saw marks / concrete, grain direction). A texture wave makes them later.
- Two-decor finishes: `body` for the carcass, `front` for the fronts, more roles (`top`, `accent`, `frame`, `handle`)
  as the catalogue shows — one finish per colour option of the collection ("Серый мокко / Дуб саттер").
- `collection.metal`: the handles' and legs' metal (`gold#…`, `chrome`, `black`).
- A profile per moulding shape the collection has (`profiles`), drawn from the close-ups.

## Output
1. `Assets/House4696/Resources/Casegoods/Designs/<model id>.json` for every module of your collections; generators in
   `tools/casegoods/gen/`.
2. `catalog.json`: finishes, profiles, collections and models of your wave (keep the file valid JSON; do not change
   Flora's entries).
3. `tools/casegoods/pilot/<model id>.png` — the check sheet of every module (it must say ok).
4. `tools/casegoods/decors.md` — the textured decors your collections need (append, one line each).
5. Notes: `tools/casegoods/notes/<wave>.md` — per collection: what the construction is, what you could not express in
   the format (engine limits the lead should add), modules you skipped and why.
6. Commit on the branch named in your task and push it.

## Rules
- Do not edit C#, Unity scenes / prefabs, other waves' designs, or Flora.
- Chairs, stools, benches and upholstered furniture are NOT in scope (a separate Blender track): skip the «Стулья» group.
- Tables are in scope when they are case furniture (tops, frames, legs as rods): dining / coffee / desk tables.
- One design per article code; colour variants of the same code are finishes, not new designs. Variants with a mirror
  or with LED light ("-01 зеркальное", "с подсветкой") that the catalogue lists as separate codes are separate designs.
